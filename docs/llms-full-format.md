# `llms-full.txt` plain-text format

Canonical reference for scrapers, chunkers, and answer engines consuming
`https://deepgrain.ai/llms-full.txt`. Generated by
`scripts/build-seo-indexes.mjs` (`toPlain()` + `buildLlmsFullTxt()`).

Keep this doc in sync whenever the generator changes.

## File layout

```
# Deepgrain, full Intelligence corpus
Last updated: YYYY-MM-DD
Articles: N
Canonical: https://deepgrain.ai/llms-full.txt
Sitemap:   https://deepgrain.ai/sitemap.xml

<intro paragraph>

<article block>
<article block>
...
```

Articles are sorted newest first by `publishedAt`.

## Article block

Each article is delimited by a 40-character `=` rule. The header is fixed-key,
one field per line, in this exact order:

```


========================================
TITLE: <string>
URL: https://deepgrain.ai/intelligence/<slug>
TRACK: deepgrain | people-ops
CATEGORY: <category-slug>
PRIMARY_CLUSTER: <cluster-slug>        # optional, omitted if absent
CLUSTERS: <slug>, <slug>               # optional, omitted if absent
PUBLISHED: YYYY-MM-DD
READ_TIME: <e.g. "8 min">
DESCRIPTION: <one line>
========================================

<plain-text body>
```

A blank line precedes each `========================================` block,
and a blank line separates the closing rule from the body.

## Body conventions

The body is plain text derived from MDX. Markdown headings (`#`, `##`, ...) are
preserved so chunkers can split on them. Inline `**bold**`, `*italic*`, and
`` `code` `` markers are stripped. Links render as `label (https://...)`. JSX
components are removed except for the three structural blocks below.

### `TLDR:` block

The MDX `<TLDR>` component is rewritten to a labelled block:

```
TLDR:
- bullet one
- bullet two
- bullet three
```

Rules:
- The literal label `TLDR:` always sits on its own line at column 0.
- Content is the trimmed inner text of `<TLDR>`, typically a markdown bullet
  list (`- ...`). The generator does not reformat bullets.
- A blank line precedes and follows the block.
- Appears at most once per article, near the top of the body.

### `KEY TAKEAWAYS:` block

The MDX `<KeyTakeaways>` component is rewritten the same way:

```
KEY TAKEAWAYS:
- takeaway one
- takeaway two
```

Rules match the `TLDR:` block. Appears at most once per article, near the end
of the body (before any auto-generated related-reading list).

### `> Takeaway` block

The MDX `<Takeaway>` component is rewritten as a single blockquote line:

```
> short takeaway sentence
```

Multiple per article are allowed, inline with the prose.

## Chunking guidance

- Split articles on the `========================================` rule.
- Within an article, the safe chunk anchors are, in priority order:
  1. `TLDR:` block (always one paragraph, ideal as a summary chunk)
  2. `KEY TAKEAWAYS:` block (always one paragraph, ideal as a closing chunk)
  3. Markdown headings (`##`, `###`)
  4. Blank-line paragraph boundaries
- The header (between the two `====` rules) is metadata, not prose. Do not
  embed it as content; index its fields separately.

## Stability contract

- Field names (`TITLE`, `URL`, `TRACK`, `CATEGORY`, `PRIMARY_CLUSTER`,
  `CLUSTERS`, `PUBLISHED`, `READ_TIME`, `DESCRIPTION`) are stable.
- Labels `TLDR:` and `KEY TAKEAWAYS:` are stable, uppercase, trailing colon,
  no surrounding punctuation.
- Field order in the header is stable.
- Optional fields (`PRIMARY_CLUSTER`, `CLUSTERS`) are omitted, never emitted
  as empty strings.

If any of the above changes, bump the `Last updated` line in this doc and
note the change in the commit message so downstream consumers can adapt.
